Featured test cases

Two compact examples suitable for recruiter review.
TC-001 · Financial integrity

Approved assignment must not deduct spending twice

PASS

Steps

  1. Set opening cash to Rp100.000.
  2. Add Rp30.000 income.
  3. Assign Rp20.000 to a member.
  4. Member marks funds received.
  5. Member submits Rp15.000 spending + Rp5.000 change with receipt.
  6. Admin approves Rp15.000 and receives Rp5.000 change.

Expected / verified

  • Cash after assignment: Rp110.000.
  • Submitting report alone does not alter cash.
  • Final cash after approval/return: Rp115.000.
  • Monthly new income remains Rp30.000.
  • Approved expense becomes Rp15.000.
  • No second deduction of the Rp15.000 spending.
TC-005 · Negative / debt flow

Invalid receipt creates exact debt and protects repayment totals

PASS

Steps

  1. Assign Rp20.000.
  2. Member reports Rp15.000 spending and Rp5.000 change.
  3. Admin validates only Rp12.000 spending, receives Rp5.000, and marks report Invalid.
  4. Record Rp3.000 debt repayment.
  5. Attempt another Rp1 repayment.

Expected / verified

  • Debt created: exactly Rp3.000.
  • Cash reflects the verified return amount.
  • Rp3.000 repayment increases central cash.
  • Repayment is not counted as new income.
  • Extra repayment after debt is fully paid is rejected.

Security & validation evidence

These controls are visible in the provided backend source. Only behaviors explicitly executed by supplied tests are marked above as PASS.

Implemented controls

CSRF token validation for POST requests, strict sessions, session ID regeneration on successful login, bcrypt password hashing with 8–72 character validation, active/archive account checks, optimistic version conflict response (HTTP 409), prepared PDO queries, and five failed login attempts triggering a 15-minute block.

Receipt validation

Backend accepts JPG, PNG, and WebP only, verifies MIME type and image validity, enforces a 5 MB limit, stores evidence outside the public asset path, and serves it only after authenticated API access.

Important testing boundary

The supplied CATATAN-UJI.txt explicitly states that MySQL/MariaDB and XAMPP were not available in the original verification environment. SQL import, real cross-browser PHP sessions, real file upload, and final browser PDF printing therefore still require integration testing in the deployment environment.

Defect statement

No confirmed unresolved software defect is documented by the supplied verification artifacts. This report intentionally does not fabricate a bug. Instead, it shows passed negative tests and clearly marks the remaining integration work as pending.
